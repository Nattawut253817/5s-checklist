# แบบฟอร์มตรวจเช็กมาตรฐาน 5ส (5S Checklist) — เวอร์ชันออนไลน์

เว็บฟอร์ม checklist ที่ให้หลายคนเข้ามาติ๊กสถานะพร้อมกันได้ และเห็นผลตรงกันแบบเกือบเรียลไทม์
โดยใช้ **Google Sheet + Google Apps Script** เป็นฐานข้อมูลกลาง (ฟรี ไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง)
และใช้ **GitHub Pages** สำหรับเผยแพร่หน้าเว็บให้ทุกคนเข้าถึงผ่านลิงก์เดียว

โครงสร้างไฟล์:

```
index.html                     ← หน้าเว็บ checklist (สิ่งที่จะขึ้น GitHub Pages)
google-apps-script/Code.gs     ← โค้ดฝั่งฐานข้อมูลกลาง (นำไปวางใน Google Apps Script)
```

---

## ขั้นตอนที่ 1: ตั้งค่าฐานข้อมูลกลาง (Google Sheet + Apps Script)

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ (ตั้งชื่อตามสะดวก เช่น "5ส Checklist ฐานข้อมูล")
2. ไปที่เมนู **Extensions > Apps Script**
3. ลบโค้ดตัวอย่างเดิมทั้งหมด แล้วคัดลอกโค้ดทั้งหมดจากไฟล์ `google-apps-script/Code.gs` ไปวางทับ
4. กด **Run** เลือกฟังก์ชัน `setupSheet` แล้วกด Run อีกครั้ง
   - ครั้งแรกระบบจะขอสิทธิ์การเข้าถึง ให้กด **Review permissions** แล้วเลือกบัญชี Google ของคุณ แล้วกด **Allow**
   - หลังรันเสร็จจะมีชีตชื่อ "Status" พร้อมหัวตารางเกิดขึ้นในไฟล์ Sheet โดยอัตโนมัติ
5. ไปที่เมนู **Deploy > New deployment**
   - กดไอคอนรูปเฟือง เลือกประเภทเป็น **Web app**
   - **Execute as:** Me (บัญชีของคุณ)
   - **Who has access:**
     - เลือก **Anyone** ถ้าต้องการให้ใครก็ได้ที่มีลิงก์เข้าถึงได้ (รวมถึงคนนอกองค์กร)
     - หรือเลือก **Anyone within [ชื่อองค์กร]** ถ้าองค์กรใช้ Google Workspace (เช่นอีเมล @ddc.mail.go.th) — **แนะนำตัวเลือกนี้** เพราะปลอดภัยกว่า จำกัดเฉพาะคนในองค์กร
   - กด **Deploy** แล้วกด **Authorize access** ตามที่ระบบขอ
6. คัดลอก **Web app URL** ที่ได้ (จะมีรูปแบบ `https://script.google.com/macros/s/xxxxxxxx/exec`)

> หมายเหตุ: ถ้าแก้ไขโค้ด Code.gs ภายหลัง ต้องไปที่ **Deploy > Manage deployments** กดไอคอนดินสอ เปลี่ยน Version เป็น "New version" แล้วกด Deploy ใหม่ ไม่งั้นระบบจะยังใช้โค้ดเวอร์ชันเก่า

---

## ขั้นตอนที่ 2: เชื่อม URL เข้ากับหน้าเว็บ

1. เปิดไฟล์ `index.html` ด้วยโปรแกรมแก้ไขข้อความ (เช่น Notepad, VS Code)
2. ค้นหาบรรทัดนี้ (อยู่ในส่วน `<script>` ท้ายไฟล์):
   ```js
   const API_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
3. แทนที่ข้อความ `PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE` ด้วย Web app URL ที่คัดลอกมาจากขั้นตอนที่ 1 (ต้องอยู่ในเครื่องหมายคำพูดเหมือนเดิม) เช่น:
   ```js
   const API_URL = "https://script.google.com/macros/s/xxxxxxxx/exec";
   ```
4. บันทึกไฟล์

---

## ขั้นตอนที่ 3: เผยแพร่ขึ้น GitHub Pages

1. เข้า [github.com](https://github.com) แล้วสร้าง repository ใหม่ (New repository) เช่นชื่อ `5s-checklist`
   - ตั้งเป็น **Public** (จำเป็นสำหรับ GitHub Pages ฟรี)
2. อัปโหลดไฟล์ `index.html` เข้า repository นี้ (ลากไฟล์วางในหน้าเว็บ GitHub ได้เลย หรือใช้คำสั่ง git ก็ได้ — โฟลเดอร์นี้เตรียม git ไว้ให้แล้ว แค่เพิ่ม remote แล้ว push):
   ```
   git remote add origin https://github.com/<ชื่อบัญชีของคุณ>/5s-checklist.git
   git branch -M main
   git push -u origin main
   ```
3. ไปที่ **Settings > Pages** ของ repository
   - Source: เลือก **Deploy from a branch**
   - Branch: เลือก **main** และโฟลเดอร์ **/ (root)**
   - กด **Save**
4. รอสักครู่ (1-2 นาที) แล้ว GitHub จะให้ลิงก์เว็บไซต์ เช่น
   `https://<ชื่อบัญชีของคุณ>.github.io/5s-checklist/`
5. แชร์ลิงก์นี้ให้ทุกคนในทีม — ทุกคนที่เปิดลิงก์จะเห็นและติ๊กสถานะเดียวกันแบบเกือบเรียลไทม์
   (หน้าเว็บจะดึงข้อมูลใหม่อัตโนมัติทุก ~12 วินาที และดึงทันทีเมื่อสลับกลับมาที่แท็บ หรือกดปุ่ม "รีเฟรชข้อมูล")

---

## ข้อควรทราบ

- ถ้ายังไม่ได้ใส่ URL ใน `API_URL` หน้าเว็บจะยังใช้งานได้ปกติ แต่จะมีข้อความแจ้งเตือนสีเหลืองว่ายังไม่เชื่อมต่อฐานข้อมูลกลาง และสถานะที่ติ๊กจะอยู่แค่ในเครื่องนั้นเครื่องเดียว ไม่ถูกแชร์ให้คนอื่น
- ปุ่ม **"ออกรายงานสรุป (HTML)"** ยังใช้งานได้ตามปกติ เพื่อเก็บสแนปช็อตผลตรวจ ณ ขณะนั้นไว้พิมพ์หรือส่งต่อ
- การตั้งค่า "Who has access: Anyone" หมายความว่าใครก็ตามที่ได้ลิงก์ Web app URL สามารถเขียนข้อมูลเข้าฐานข้อมูลได้ (ไม่ใช่แค่คนที่เปิดหน้าเว็บ checklist) จึงไม่ควรเผยแพร่ URL ของ Apps Script ให้คนทั่วไป (เผยแพร่แค่ลิงก์หน้าเว็บ GitHub Pages ก็พอ) และถ้าเป็นไปได้แนะนำให้ใช้ตัวเลือก "Anyone within [องค์กร]" แทน
